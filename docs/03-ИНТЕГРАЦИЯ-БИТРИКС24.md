# Интеграция с Битрикс24

Как ПУЛЬС подключается к порталу, читает открытые линии и пишет сотрудникам.
Документ для администратора портала и разработчика.

---

## 1. Схема

```
Клиент (Telegram / WhatsApp / чат на сайте / Битрикс24 Network)
        │
        ▼
Открытая линия Битрикс24  ──►  Чат «клиент + сотрудник»
        │                              │
        │  ONIMBOTV2MESSAGEADD         │  история, участники, CRM
        ▼                              ▼
   Бот ПУЛЬС (supervisor)  ◄────  REST API Битрикс24
        │
        ▼
   Платформа ПУЛЬС
   ├─ хранилище сообщений (PostgreSQL)
   ├─ разбор: метрики, обещания, тон, риски
   ├─ оценка и красная зона
   ├─ уведомления сотруднику / руководителю / собственнику
   └─ веб-панель и отчёты
```

Два варианта чата:

- **A. Классическая открытая линия.** Клиент пишет из внешнего канала, Битрикс24
  создаёт чат и сессию. Бот подключается к линии как чат-бот.
- **B. Групповой чат с клиентом.** Компания ведёт клиента в групповом чате
  Битрикс24 (в том числе с внешним участником). Бот добавляется в чат как
  участник-наблюдатель.

Логика разбора одинаковая; отличается способ получения чата.

---

## 2. Что нужно от портала

- Тариф Битрикс24 с открытыми линиями и REST API.
- Права администратора для создания локального приложения.
- Scope: `imbot`, `imopenlines`, `tasks`, `crm`, `user`.
- Публичный HTTPS-адрес платформы (для webhook) **или** режим fetch
  без входящего URL.
- Часовой пояс компании (для сроков и утренней сводки).
- Список открытых линий и ответственных сотрудников.

Проверить ревизию API: `imbot.v2.Revision.get`.

## 3. Регистрация бота

Бот регистрируется методом `imbot.v2.Bot.register` от имени приложения или
входящего вебхука.

```json
{
  "fields": {
    "code": "pulse_observer",
    "botToken": "<секретный_токен_бота>",
    "type": "supervisor",
    "isSupportOpenline": true,
    "eventMode": "webhook",
    "webhookUrl": "https://pulse.example.ru/webhook/bitrix24",
    "properties": {
      "name": "ПУЛЬС",
      "workPosition": "контроль качества",
      "color": "lime"
    }
  }
}
```

Ключевые параметры:

| Параметр | Значение | Зачем |
|---|---|---|
| `type` | `supervisor` | Видит все сообщения в чатах, где состоит, без упоминания `@bot` |
| `isSupportOpenline` | `true` | Работа в открытых линиях |
| `eventMode` | `webhook` или `fetch` | Доставка событий |
| `webhookUrl` | HTTPS-адрес | Приём событий |
| `botToken` | секрет | Проверка подлинности при вебхуке |

`supervisor` — системный наблюдатель. Он не отвечает клиенту и не мешает
оператору, но получает все сообщения. Это ровно роль ПУЛЬСа.

Ответ содержит `bot.id`. Сохраните его в настройках платформы.

> Важно: пока бот не подключён к открытой линии, события из неё не приходят.
> Регистрация сама по себе не добавляет бота в чат сессии.

## 4. Подключение к линии

### Вариант A. Открытая линия

1. Контакт-центр → Открытые линии → нужная линия → настройки чат-бота.
2. Выбрать ПУЛЬС и момент подключения: «с первого сообщения» или «после оператора».
3. Для режима наблюдателя достаточно, чтобы бот был в сессии, но не отвечал.
4. Отправить тестовое сообщение в линию и проверить событие.

### Вариант B. Групповой чат

1. Бот должен быть участником чата. В интерфейсе Битрикс24 бота добавляет
   владелец чата или администратор.
2. Если чат создаётся автоматически, добавление бота включите в сценарий
   создания (робот / приложение).
3. Проверьте, что событие `ONIMBOTV2MESSAGEADD` приходит на сообщения клиента
   и сотрудника.

Для добавления **пользователей** в чат есть `imbot.v2.Chat.User.add`
(`dialogId: "chat{id}"`, `userIds`). Для добавления самого бота в произвольный
чат используйте штатное приглашение бота или подключение к линии — метод
добавляет пользователей, а не ботов.

## 5. События

| Событие | Когда приходит | Что делаем |
|---|---|---|
| `ONIMBOTV2MESSAGEADD` | Новое сообщение в чате, где бот участник | Сохраняем, разбираем |
| `ONIMBOTV2MESSAGEUPDATE` | Сообщение изменено | Обновляем текст и разбор |
| `ONIMBOTV2MESSAGEDELETE` | Сообщение удалено | Помечаем удалённым |
| `ONIMBOTV2JOINCHAT` | Бота добавили в чат | Подтягиваем историю и участников |
| `ONIMBOTV2COMMANDADD` | Слэш-команда боту | Необязательно |
| `ONOPENLINEMESSAGEADD` | Событие открытой линии (если приложение — коннектор) | Дополнительный источник |
| `OnSessionStart` / `OnSessionFinish` | Начало и конец сессии | Связываем чат и сессию |

Пример тела `ONIMBOTV2MESSAGEADD` (сокращённо):

```json
{
  "event": "ONIMBOTV2MESSAGEADD",
  "data": {
    "bot": { "id": 456 },
    "chat": { "id": 112, "dialogId": "chat112", "entityType": "LINES" },
    "message": {
      "id": 80964,
      "date": "2026-11-20T09:12:00+05:00",
      "text": "Ирина, добрый день! Проверьте, пожалуйста, НДС",
      "authorId": 1985
    },
    "user": { "id": 1985, "name": "Марина Ковалёва" }
  },
  "auth": {
    "domain": "buh-osnova.bitrix24.ru",
    "member_id": "...",
    "application_token": "..."
  }
}
```

Обработчик (псевдокод):

```python
@app.post("/webhook/bitrix24")
async def handler(request: Request):
    payload = await request.json()
    if payload.get("event") != "ONIMBOTV2MESSAGEADD":
        return {"ok": True}

    data = payload["data"]
    chat_id = data["chat"]["id"]
    message = data["message"]

    # 1. Проверка подлинности
    verify_application_token(payload["auth"]["application_token"])

    # 2. Идемпотентность
    if exists(message["id"]):
        return {"ok": True}

    # 3. Сохранение
    save_message(
        chat_id=chat_id,
        message_id=message["id"],
        author_id=data["user"]["id"],
        text=message["text"],
        created_at=message["date"],
    )

    # 4. Разбор и оценка
    analyze_chat_async(chat_id)

    # 5. Уведомления по правилам
    maybe_notify(chat_id)

    return {"ok": True}
```

Ответ должен быть быстрым: тяжёлую работу выносите в очередь. Битрикс24
повторяет событие при ошибке, поэтому идемпотентность обязательна.

## 6. Чтение истории и контекста

### Открытая линия

`imopenlines.session.history.get`:

```json
{
  "CHAT_ID": 1763,
  "LIMIT": 200
}
```

Ответ содержит `sessionId`, `messages`, `users`, `hasNextPage`, `nextId`,
`nextDate`. Для следующей страницы передайте `LAST_ID` и `LAST_DATE`.

### Групповой чат

`im.dialog.messages.get` (бот — участник):

```json
{
  "DIALOG_ID": "chat112",
  "LIMIT": 50
}
```

Для наблюдателя доступен `imbot.v2.Chat.Message.getContext` — соседние
сообщения вокруг известного `messageId`. Это удобно при первом подключении
к чату, когда нужно восстановить контекст.

### Связь с CRM

- `imopenlines.crm.chat.get` — чат по объекту CRM;
- `imopenlines.dialog.get` — данные диалога, включая `entity_data_1`
  (в шестом элементе — `SESSION_ID`);
- `crm.deal.get`, `crm.item.get` — сумма договора и ответственный;
- `user.get` — сотрудники и их ID.

## 7. Запись в Битрикс24

ПУЛЬС пишет **не в чат клиента**, а в личные каналы сотрудников и задачи.

### Сообщение сотруднику

`imbot.v2.Chat.Message.send` в личный диалог сотрудника с ботом. Текст:

```
Ирина, по клиенту «Ромашка» клиент ждёт ответа 2 ч 25 мин.
Обещание «вернусь в течение часа» просрочено. Ответьте, пожалуйста,
и подтвердите новый срок.
```

### Задача

`tasks.task.add`:

```json
{
  "fields": {
    "TITLE": "Ответить клиенту «Ромашка» и подтвердить срок по НДС",
    "DESCRIPTION": "Клиент ждёт 2 ч 25 мин. Обещание просрочено. Срок сдачи НДС — 25.11.",
    "RESPONSIBLE_ID": 27,
    "DEADLINE": "2026-11-20T18:00:00+05:00",
    "PRIORITY": "2"
  }
}
```

### Эскалация

Если порог превышен, продублируйте руководителю и собственнику. Канал:
личный чат бота или уведомление Битрикс24. В тексте — клиент, причина,
ссылка на чат, сумма риска.

### Комментарий в CRM

Опционально: `crm.timeline.comment.add` — короткий итог разбора в таймлайн
сделки. Не дублируйте туда всю переписку.

## 8. Режимы доставки

### Webhook (рекомендуется)

- мгновенные события;
- нужен публичный HTTPS;
- проверяйте `application_token`;
- отвечайте 200 быстро, обработку — в очередь.

### Fetch (проще для пилота)

- `imbot.v2.Event.get` забирает очередь событий;
- не нужен публичный URL;
- опрос раз в 5–15 секунд;
- подходит для одной линии и теста.

### Гибрид

Webhook для сообщений, периодический опрос истории для восстановления
пропущенного. Это защита от сетевых сбоев.

## 9. Сопоставление сущностей

| Битрикс24 | ПУЛЬС |
|---|---|
| `chat.id` | `chat.external_id` |
| `message.id` | `message.external_id` (уникальный) |
| `user.id` сотрудника | `employee.bitrix_user_id` |
| CRM-компания / контакт | `client.crm_id` |
| Сумма сделки | `client.contract_value` |
| `SESSION_ID` | `chat.session_id` |
| Линия | `chat.line` |

Клиент определяется по CRM-связи чата. Если связи нет — по имени и каналу,
с пометкой «не привязан». Сотрудник — по автору сообщения и участникам чата.

## 10. Надёжность

- **Идемпотентность.** Уникальный индекс на `message.external_id`.
- **Очередь.** Redis / RabbitMQ / встроенная таблица outbox.
- **Ретраи.** Экспоненциальная задержка, максимум 5 попыток.
- **Лимиты.** Не больше 2 исходящих запросов в секунду на портал; батчинг.
- **Восстановление.** При старте догрузить историю за последние 24 часа.
- **Мониторинг.** Health-check, счётчик ошибок, алерт при молчании событий
  больше 10 минут в рабочее время.

---

## 11. Безопасность и данные

- HTTPS, проверка `application_token` и `member_id`.
- Токены — в секретах, не в репозитории.
- Доступ к панели — OAuth Битрикс24 и роли.
- В базе — только открытые линии, без личных чатов.
- Персональные данные: минимизация, шифрование бэкапов, retention 90 дней.
- 152-ФЗ: серверы в РФ, согласие сотрудников, уведомление клиентов
  в политике конфиденциальности.
- Аудит действий: кто открывал чат, кто ставил задачу, кто менял правила.

## 13. Ограничения, которые нужно проверить на портале

1. **Тариф.** История открытых линий и часть методов статистики зависят от тарифа.
2. **Тип чата.** Для классической линии бот подключается к линии; для группового
   чата — добавляется участником. Проверьте оба сценария на пилотной линии.
3. **Внешние участники.** В групповом чате с клиентом из другого домена
   убедитесь, что бот видит сообщения внешнего участника.
4. **События.** В чате открытой линии бот получает все сообщения клиента без
   упоминания; в обычном групповом чате — согласно типу `supervisor`.
5. **История.** Глубина хранения в Битрикс24 может быть меньше, чем нужна.
   Восстановление — через `imopenlines.session.history.get`.
6. **Лимиты REST.** Уточните лимиты тарифа и заложите очередь.
7. **Смена API.** `imbot.*` устарел; используйте `imbot.v2.*`. Следите за
   журналом изменений.
