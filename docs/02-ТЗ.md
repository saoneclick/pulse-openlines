# ПУЛЬС — техническое задание

Версия 0.1 · демонстрационный контур

## 1. Цель и границы

### 1.1. Цель

Создать платформу контроля открытых линий Битрикс24 для бухгалтерской компании.
AI-бот присутствует в чатах «клиент + сотрудник», анализирует переписку и даёт
собственнику ответ на три вопроса:

1. Что происходит в открытых линиях сейчас?
2. Что хорошо и что плохо — с фактами и цитатами?
3. Что сделать сегодня, чтобы не потерять клиента, деньги или срок?

### 1.2. Входит в объём

- подключение к Битрикс24 как бот-наблюдатель (`imbot.v2`, тип `supervisor`);
- приём и хранение сообщений открытых линий;
- разбор переписки: ответы, ожидание, обещания, тон, риски, сроки;
- оценка чата и сотрудника;
- личные подсказки сотруднику;
- эскалация руководителю и собственнику;
- веб-панель: пульс, чаты, люди, обещания, отчёт, настройки;
- утренняя сводка и пятничный отчёт;
- демо-контур с реалистичными данными.

### 1.3. Не входит

- автоматические ответы клиентам (кроме отдельного флага на безопасные темы);
- налоговые консультации и расчёты;
- замена CRM, Tasks и телефонии;
- чтение личных чатов, почты, звонков;
- мобильное приложение (адаптивная веб-панель — да).

## 2. Пользователи и роли

| Роль | Видит | Действия |
|---|---|---|
| **Собственник** | Все линии, все чаты, люди, суммы, риски, отчёты | Настройки, эскалации, задачи, отчёты |
| **Руководитель отдела** | Свои линии, все чаты, люди, без финансов клиентов | Задачи, разбор, эскалации |
| **Бухгалтер** | Только свои чаты и свои подсказки | Отметить «разобрано», ответить клиенту в Битрикс24 |
| **Администратор** | Подключение, линии, правила, доступы | Техническая настройка |

Аутентификация: вход через Битрикс24 (OAuth) в боевом контуре; в демо — без входа.

## 3. Сценарии

### UC-1. Подключение линии

1. Администратор создаёт локальное приложение Битрикс24 со scope `imbot`, `imopenlines`, `tasks`, `crm`, `user`.
2. Регистрирует бота `imbot.v2.Bot.register` с `type=supervisor`, `isSupportOpenline=true`.
3. Подключает бота к открытой линии в Контакт-центре.
4. Платформа проверяет: событие `ONIMBOTV2MESSAGEADD` приходит, история читается.
5. В панели появляется линия и первые чаты.

### UC-2. Разбор нового сообщения

1. Приходит событие с `chatId`, `messageId`, текстом, автором, временем.
2. Сообщение сохраняется идемпотентно (`messageId` уникален).
3. Обновляются метрики чата: первый ответ, средний ответ, ожидание.
4. LLM/правила размечают смысл: обещание, риск, тон, инициатива.
5. Пересчитывается оценка и вердикт.
6. При нарушении порога создаётся уведомление или эскалация.

### UC-3. Утренняя сводка

1. В 09:00 по часовому поясу компании собираются активные чаты за сутки.
2. Формируется короткий текст: пульс, красная зона, хорошее, плохое, план.
3. Отправляется собственнику в личный чат бота.
4. Дублируется на экране «Пульс».

### UC-4. Разбор чата

1. Собственник открывает чат из красной зоны.
2. Видит вердикт, метрики, находки «хорошо/плохо» с цитатами.
3. Видит обещания и статус.
4. Может написать сотруднику, поставить задачу, открыть чат в Битрикс24.

### UC-5. Контроль обещаний

1. Из сообщений извлекаются обязательства и сроки.
2. Обещание связывается с сообщением-источником.
3. При наступлении срока проверяется результат: «готово», «отправил», закрытие задачи.
4. Просрочка попадает в список и в оценку.

### UC-6. Риск ухода

1. В переписке появляются маркеры: «другой бухгалтер», «уходим», «жалоба», «суд», «штраф».
2. Чат получает критичный флаг.
3. Собственник получает мгновенное уведомление.
4. В панели показывается сумма договора под риском.

### UC-7. Сотрудник на больничном

1. Сотрудник недоступен, чат не отвечает дольше порога.
2. Бот проверяет: есть ли передача диалога, есть ли задачи.
3. Если передачи нет — критичное событие «клиент без ответственного».
4. Руководитель назначает замену, бот фиксирует передачу.

### UC-8. Недельный отчёт

1. В пятницу собираются метрики за 7 дней.
2. Формируются разделы: главное, хорошо, плохо, деньги, люди, план.
3. Отчёт доступен на экране, копируется, скачивается в Markdown, печатается в PDF.

## 4. Функциональные требования

## 5. Модель данных

```
employee   (id, name, role, initials, bitrix_user_id, since, is_active)
client     (id, name, kind, industry, contact, crm_id, contract_value)
chat       (id, external_id, client_id, employee_id, line, topic, tags,
            status, opened_at, last_activity, score, verdict, summary,
            risk_amount, first_response_min, avg_response_min, waiting_min)
message    (id, chat_id, author, author_name, text, created_at, meta)
finding    (id, chat_id, employee_id, message_id, code, tone, severity,
            title, detail, quote, recommendation)
promise    (id, chat_id, employee_id, text, due_at, status, kept_at,
            source_message_id)
task       (id, chat_id, employee_id, title, due_at, status)
metric_day (day, score, critical_count, avg_response_min, chats_count,
            promises_kept_pct)
setting    (key, value JSON)
action_log (id, chat_id, kind, payload, created_at)
```

Индексы: `message.chat_id`, `message.created_at`, `chat.last_activity`,
`finding.chat_id`, `promise.due_at`.

Хранение: PostgreSQL в production, SQLite в демо. Срок хранения сообщений —
90 дней по умолчанию, агрегаты — 24 месяца.

## 6. API платформы

| Метод | Назначение |
|---|---|
| `GET /api/state?period=7` | Полный срез для панели |
| `GET /api/chats/{id}` | Детали чата |
| `POST /api/chats/{id}/notify` | Сообщение сотруднику |
| `POST /api/chats/{id}/task` | Задача сотруднику |
| `POST /api/settings` | Сохранить настройки |
| `POST /api/demo/reset` | Пересобрать демо |

Ответ `state` содержит: `meta`, `overview`, `chats`, `people`, `promises`,
`report`, `settings`. Формат стабилен для SPA.

## 7. Оценка

Полная методика — `04-МЕТОДИКА-ОЦЕНКИ.md`.

Кратко:

```
score = clamp(0..99, 100 − Σ штрафы + min(6, Σ бонусы))
```

Штрафы: critical 20, high 12, medium 7, low 3.
Бонусы: critical 6, high 5, medium 3, low 1.
Вердикт: critical при наличии critical-находки или score < 60;
watch при high-находке или score < 85; иначе ok.

Приоритеты находок для красной зоны:
`client_risk > no_handoff > client_waiting > promise_overdue > rude >
deadline_risk > slow_first > client_upset > ...`

## 9. Этапы

### Этап 1. Демо-контур (готово)

- самостоятельная панель с демо-данными;
- 11 чатов, 5 сотрудников, 3 линии;
- разбор, оценка, отчёт, настройки;
- без подключения к реальному порталу.

### Этап 2. Пилот (2–3 недели)

- подключение одной линии;
- чтение событий и истории;
- разметка реальных чатов, ручная проверка точности;
- подсказки сотрудникам;
- утренняя сводка.

### Этап 3. Production (4–6 недель)

- все линии, роли, OAuth;
- задачи и CRM;
- недельный отчёт;
- регламент и обучение команды;
- мониторинг и поддержка.

## 10. Критерии приёмки

1. Бот получает все сообщения пилотной линии без упоминания `@bot`.
2. История чата восстанавливается после перезапуска.
3. Первый ответ и ожидание совпадают с ручным замером (±1 минута).
4. Обещание из переписки появляется в списке с верным сроком.
5. Просрочка обещания меняет оценку и попадает в красную зону.
6. Риск ухода вызывает уведомление собственнику.
7. Утренняя сводка приходит в 09:00.
8. Отчёт формируется за 7 дней и выгружается.
9. Роли не дают бухгалтеру видеть чужие чаты.
10. Ложные срабатывания можно отменить, и это учитывается в обучении.

## 11. Риски и допущения

| Риск | Мера |
|---|---|
| Бот не подключён к линии — события не приходят | Чек-лист подключения, тестовое сообщение |
| Портал ограничивает историю | Читать через `imopenlines.session.history.get` и контекст |
| LLM ошибается в тоне | Цитата + ручная отмена, порог уверенности |
| Сотрудники сопротивляются | Прозрачное включение, пилот, коучинг |
| Персональные данные | Минимизация, retention, доступ по ролям |
| Тариф Битрикс24 не даёт нужные методы | Проверка на пилоте, fallback на выгрузку истории |

Допущения:

- сообщения открытой линии доступны боту как участнику;
- в компании есть CRM-связь клиента и сумма договора;
- налоговый календарь ведётся в одном справочнике.

## 12. Текущая реализация

Демо-контур находится в этом репозитории:

- `app/` — FastAPI, SQLAlchemy, SQLite, демо-сид, движок разбора;
- `app/ui/` — панель без сборки (HTML/CSS/JS);
- `docs/` — продуктовая и техническая документация.

Запуск:

```bash
pip install -r requirements.txt
python run.py
# http://127.0.0.1:8090
```

Демо-данные пересобираются кнопкой «Сбросить демо» или `POST /api/demo/reset`.
